# Atexgrove Known Issues

**Status date:** 2026-10-27

This list distinguishes current gaps from planned work. It is not a production-readiness claim.

| Item | Current status | Planned direction |
| --- | --- | --- |
| Legacy duplicate response/resume timeline line | **Presentation-only heuristic:** `caseTimelineEvents` hides an unambiguous old fixed “resume” companion with the same case, actor and transition, within one second (also matching visibility and adjacent milestones; equal-timestamp pairs are handled conservatively). Historical rows and audits are unchanged in the database; unmatched/ambiguous history remains visible. | Preserve history; new 026 responses write one linked milestone. |
| Corrections after submission | **Deliberate restriction:** customers cannot correct old submitted cases or add/replace evidence in `submitted`, `assigned` or `in_review`; they must wait for a staff information request. | Staff can request information to open the preparation window. No general customer-edit workflow is implemented. |
| Legacy information request without a milestone | **Fails closed:** no safe response token exists. Staff cannot manually resume review to repair it. | A reviewed forward repair of the request linkage is required, or close/cancel and create a new request. Never release pending files as a workaround. |
| Customer/staff context separation and role display | **Code fix merged and schema hosted:** [PR #17](https://github.com/bakareolamilekan365-tech/ATEXGROVE/pull/17) separates customer queries and adds role/workspace display. Migration `020_customer_safe_status.sql` was applied to hosted Supabase on 2026-10-20. | Operationally verify the merged UI with separate customer, staff and dual-role accounts. |
| Staff UI displays raw user IDs | **Open:** work-queue/detail screens show identifiers rather than safe display names. | Resolve names through an authorized profile/staff view without broadening profile access. |
| Privacy, Terms and cookie pages | **Not implemented.** | Required, with appropriate legal/privacy review, before real customer documents or production use. |
| Account deletion versus `on delete restrict` | **Open design issue:** evidence/customer references can block Auth-user deletion. | Define retention, anonymization, legal hold and deletion behavior before real use. |
| Customer retrieval of uploaded evidence | **Not implemented:** customers can upload and see metadata but cannot download their own stored object. | Add an explicitly authorized, audited customer retrieval path in a later reviewed slice. |
| Abandoned direct-upload objects | **Accepted November preview limit:** a browser-direct upload can finish in private Storage but remain unregistered if the page closes or connectivity fails before finalization. Failed server verification/registration still attempts cleanup. | Use the conservative manual procedure in `RUNBOOK.md`; durable reservations, expiry and automated cleanup are deferred until after the preview. |
| Pre-registration quota concurrency | **Accepted November preview limit:** the ten-file rule counts registered `case_evidence` rows. Simultaneous private objects can exist before `register_case_evidence` authoritatively enforces the registered-evidence limit. | Accept only for the small synthetic cohort; design durable reservation/concurrency protection before wider or real-document use. |
| Staff upload notifications | **Not implemented:** draft uploads do not enter the staff queue or send notifications; the notification function is a placeholder and there is no delivery mechanism. | No notification system is part of the current fix. |
| Virus scanning | **Unavailable in the current Free-plan slice.** Files are untrusted, allowlisted and download-only. | Add a replaceable malware-scanning integration before real-document use where required. |
| Role-based onboarding routing | **Undecided / not implemented.** | Keep onboarding neutral until the product decision is recorded; do not infer staff access from platform role. |
| Login/session navigation and `?next=` | **Corrected in `fix/login-session-and-docs-reconciliation`; operational verification pending:** login now uses one full-document request after successful authentication, validates internal `?next=` destinations and middleware preserves refreshed cookies on redirects. | Verify immediate sign-in, customer/staff workspace switching, account switching, sign-out and recovery completion in the isolated preview environment. Do not claim browser acceptance from unit/integration tests alone. |
| Large-upload staging acceptance | **Repository transport corrected; operationally unverified:** evidence bytes now travel from the authenticated browser directly to private Supabase Storage, avoiding the Netlify buffered function payload. CI cannot prove deployed reliability. | Prove approximately 1 MiB, 5 MiB, 9 MiB and near-10 MiB uploads in isolated Netlify/Supabase staging before invitations. Investigate TUS if standard direct upload is unreliable; do not silently lower the limit. |
| Node/runtime compatibility | **Open preview gate:** current CI uses Node 20, while installed Supabase JavaScript packages declare Node 22 or later. PR #30 CI passed but emitted engine warnings. | Move CI and the eventual Netlify runtime to a supported Node version in a separate reviewed configuration change, then rerun all gates. |
| Dependency audit findings | **Open security review:** the latest merged-baseline install reported dependency vulnerabilities. A green build does not resolve them. | Triage affected packages and reachable risk separately; do not run an automatic forced major-version upgrade. |
| `verification_case_number_counters` advisor item | **Informational / hosted confirmation pending:** migration 024 enables RLS, removes client and service-role table grants, defines no client policy and accesses the counter only through the reviewed submit `SECURITY DEFINER` function. | Confirm the hosted advisor/privilege evidence read-only. Do not add an ordinary client policy merely to silence an intentional private-table advisory. |
| Leaked-password protection | **Accepted private-preview limitation:** reported disabled on the existing Supabase Free project; [Supabase documents](https://supabase.com/docs/guides/auth/password-security) the feature as Pro-and-above. | Do not claim it is enabled or buy a plan in this task. Reassess before production or a plan decision; use fictional preview data and individual accounts. |
| Updated staff dashboard reference | **Design only:** the Verification Lead PDF includes handover, second review, workload/capacity, Staff ID login and authenticator concepts that are not all implemented. | November may adopt styling only for real functions. Staff identity redesign and related controls belong to the January 2027 workstream. |
| Data API grants for new public tables | **Upcoming platform change:** from 2026-10-30, Supabase stops automatically granting Data API access to newly created tables in `public`. Existing tables are unaffected. | Every new-table migration must grant `SELECT` explicitly to `authenticated` only, grant `service_role` access only as needed, grant no access to `anon`, and keep writes behind secured RPCs. RLS remains required and separate from grants. |
| Final logo application assets | **Resolved:** owner-confirmed logo, mark and wordmark SVGs are in `public/logo`; the mark is used in the staff header and as the favicon. | No open action. |
| Customer and staff roles on one account | **By design:** one account may be both a customer and staff member; the identities are kept in separate tables. Customer and staff screens must keep their data contexts separate. | Keep dual-role accounts in regression tests. |
| Draft retention | **Open decision:** draft cases and uploaded files, including discarded drafts, are retained. No automatic cleanup or customer deletion of draft evidence exists yet. | Decide retention, deletion, and legal-hold behavior before real customer documents are accepted. |
| Idle session timeout | **Not implemented:** the Supabase session persists in its cookie until it expires or the user signs out. | Timeout policy is an open decision; no idle timeout is claimed. |
| FCT area names | **Prototype list:** council areas are a starter list, not official. | Owner confirmation is still needed before presenting them as authoritative. |
| Assignment event visibility, strict council/area input and phone contact | **Migration 022 hosted** (applied 2026-10-23); PR #24 follow-up code and tests merged. | Hosted state is separate from realistic multi-account operational verification. |

Operational verification gaps are maintained in [STATUS.md](STATUS.md), not duplicated here.
